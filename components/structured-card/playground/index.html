Structured Card

Beta

Structured cards provide a pre-configured card layout with dedicated slots for a title, header actions, body content, and footer actions.

Overview

The structured card is a pre-configured card layout optimized for common patterns in Tyler Cloud applications. Its slot-based architecture provides designated areas for a title, header actions, body content, and footer buttons, so teams build consistent card UIs without hand-assembling the same header and footer structure every time. It’s ideal for table containers and self-contained content sections that need their own actions.

Usage

forge-structured-card lays out a card through named slots — before-title, title, header-actions, after-header-actions, body, footer-start, footer-secondary-action, and footer-primary-action — plus heading-level to set the title’s semantic level and body-spacing to remove body padding for edge-to-edge content. Every slot is optional, and the header and footer hide when nothing is slotted into them. Use it when a card needs a header, body, and footer; for a card that only groups content with no header or footer, use a plain forge-card instead.

Slot locations

1
Before titleA back button or navigation icon, before the title.
Project details
2
TitleThe card's title, styled as heading3 and exposed at heading-level (2 by default).
Draft
3
Header actionsStatus indicators or controls at the end of the header.
4
After header actionsIcon buttons that run up against the card's edge, like an overflow menu or close button.
5
BodyThe card's main content. Padded by default; set body-spacing to none for edge-to-edge content.
Learn more
6
Footer startControls at the start of the footer, like extra buttons opposite a paginator.
Cancel
7
Footer secondary actionThe alternative action, like Cancel.
Save
8
Footer primary actionThe card's main action, always last in the footer.

Rules

Do
Use a structured card when a card needs a header, body, and footer, rather than hand-building one from a card, scaffold, and toolbars.Set heading-level so the title fits the page's heading hierarchy.Put icon buttons that should sit against the card's edge, like an overflow menu or close button, in after-header-actions.Put status indicators, like a badge, in header-actions.Set body-spacing="none" for full-width body content, like a table.Put the main action in footer-primary-action and the alternative, like Cancel, in footer-secondary-action.
Don't
Don't style the title with a heading class — the card applies heading3 to the title slot.Don't put more than one primary action in the footer.Don't use a structured card for a simple grouping of content with no header or footer — use a card.

With a form

Put a form in the body slot and its submit and cancel buttons in the footer action slots. Use header-actions for status, like a badge.

A structured card containing a form, with a status badge in the header and actions in the footer.

Tables

Set body-spacing="none" (or the bodySpacing property) for full-width content like a table. It removes the body padding and the footer’s bottom padding so the content runs edge to edge. Put a paginator in footer-primary-action.

A structured card containing a table, with refresh and download icon buttons in the header and a paginator in the footer.

PreviewCode
<forge-structured-card heading-level="2" body-spacing="none" class="w-[600px]">
  <div slot="title">
    User Management
  </div>
  <forge-icon-button aria-label="Refresh data" slot="after-header-actions">
    <forge-icon name="refresh">
    </forge-icon>
  </forge-icon-button>
  <forge-icon-button aria-label="Download report" slot="after-header-actions">
    <forge-icon name="download">
    </forge-icon>
  </forge-icon-button>
  <forge-table slot="body" id="structured-card-table">
  </forge-table>
  <forge-paginator slot="footer-primary-action" page-size="5" total="25" page-index="0">
  </forge-paginator>
</forge-structured-card>

Properties
PropertyAttributeTypeDefaultDescription
headingLevel—HeadingLevel2Controls the semantic heading level for the title content. Defaults to `2` (h2). Use this to maintain proper heading hierarchy in your document structure.
bodySpacing—'none' | 'default''default'Controls the spacing applied to the body section. Defaults to `default`. - `default`: Applies standard padding to the body section. - `none`: Removes padding from the body section for full-width content like tables.
Slots
NameDescription
before-titleContent displayed before the title in the header
titleThe title content displayed in the header
header-actionsAction buttons or controls displayed at the end of the header
after-header-actionsContent displayed after the header actions, designed specifically for icon buttons that need to run up against the card edge (ie: menu icon button)
bodyThe main body content of the card
footer-startContent displayed at the start of the footer (e.g., pagination controls)
footer-secondary-actionSecondary action button displayed at the end of the footer
footer-primary-actionPrimary action button displayed at the end of the footer
CSS Custom Properties
NameDescription
--forge-structured-card-body-heightControls the height of the body content. Defaults to `auto`.

Heading level

The title is exposed as a heading, at level 2 by default. Set heading-level so it fits the page’s heading hierarchy — for example, 3 for a card under a section’s h2.

Labeling icon buttons

Give every icon button in the header an aria-label, such as “More actions” or “Back”, since it has no visible text.

Tab order

A structured card is a container, not an interactive control. Its slotted controls follow the natural tab order: header, then body, then footer.
