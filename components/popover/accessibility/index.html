Popover

A popover floats content above the page, positioned relative to the trigger element that anchors it.

UsageAPIPlaygroundAccessibility
Open popover

Usage

forge-popover floats its content above the page, anchored to a trigger element by anchor (the trigger’s id), through placement, triggerType, preset, and arrow. Use it for content that needs more than a couple of words — a form, a set of options, or a preview — triggered by clicking, hovering, or focusing another element. For a one- or two-word label, use a tooltip instead; forge-popover is also the foundation other components build on, like menu, select, and date picker.

Rules

Do
Use a popover when the content is more than a couple of words — a definition, a form, or extra context for a component.Set anchor to the id of the exact element that triggers the popover.Give a non-modal popover a way to close explicitly if dismissing it accidentally could lose the user's work.
Don't
Don't use a popover for a one- or two-word label — use a tooltip instead.Don't nest a popover inside another popover's content.Don't rely on a popover alone for content essential to completing a task on a touch device without a comparable trigger type.

Basic usage

Set anchor to the id of the trigger element; the popover positions itself relative to it automatically.

A popover anchored to a button, structured with a scaffold.

<forge-button id="popover-trigger" variant="raised">
  Show Popover
</forge-button>
<forge-popover anchor="popover-trigger" placement="bottom" position-strategy="fixed" hide="anchor-hidden">
  <forge-scaffold>
    <forge-toolbar no-border slot="header">
      <h2 class="forge-typography--heading4" slot="start">
        Popover Title
      </h2>
    </forge-toolbar>
    <div slot="body" style="width: 300px; padding: var(--forge-spacing-medium);">
      Popover content
    </div>
    <forge-toolbar no-border slot="footer">
      <forge-button slot="end" variant="filled">
        Close
      </forge-button>
    </forge-toolbar>
  </forge-scaffold>
</forge-popover>

Popover vs. dialog

Popovers are transient and non-modal — anchored to a trigger, they don’t block interaction with the rest of the page. Dialogs are typically modal and reserved for content that demands the user’s immediate attention, like a confirmation or a form that must be completed before moving on. The line can blur in practice; when it’s genuinely ambiguous which one fits, weigh the UX and accessibility implications of blocking (or not blocking) the rest of the page rather than defaulting to one or the other.

Non-modal

forge-popover has no semantic meaning by default — it’s up to you to add ARIA attributes appropriate to its content. Set role="dialog" and aria-modal="false" for a popover that doesn’t trap focus or block interaction with the rest of the page — useful for a lightweight, persistent form.

A non-modal popover that doesn't block interaction with the rest of the page.

<script type="module">
import { ToastComponent } from "@tylertech/forge/toast";
const popover = document.querySelector("forge-popover");
const input = popover?.querySelector('input[name="your-name"]');
const [cancelButton, saveButton] = popover ? Array.from(popover.querySelectorAll('forge-toolbar[slot="footer"] forge-button')) : [];
function handleInput() {
  if (saveButton) {
    saveButton.disabled = !input?.value;
  }
}
function close() {
  if (input) {
    input.value = "";
  }
  if (saveButton) {
    saveButton.disabled = true;
  }
  if (popover) {
    popover.open = false;
  }
}
function save() {
  if (input?.value) {
    ToastComponent.present({ message: `Hello, ${input.value}!` });
  }
  close();
}
input?.addEventListener("input", handleInput);
cancelButton?.addEventListener("click", close);
saveButton?.addEventListener("click", save);
popover?.addEventListener("forge-popover-beforetoggle", (event) => {
  const { detail } = event;
  if (detail.newState === "closed" && input?.value) {
    event.preventDefault();
    ToastComponent.present({ message: "You have unsaved changes." });
  }
});
</script>

Popovers are typically triggered by user interaction, such as clicking a button or hovering over an element.

No default semantics

A popover has no semantic meaning by default. Add the appropriate ARIA attributes to the popover itself, or to the content inside it, based on what that content actually needs.

Popover vs. dialog

Popovers are transient and non-modal — they don’t block interaction with the rest of the page. Dialogs are typically modal and demand the user’s immediate attention. When a design calls for something in between, weigh the UX and accessibility implications of each rather than defaulting to one.

To make a popover behave like a non-modal dialog, add role="dialog" and aria-modal="false" — this tells screen readers it’s a dialog that doesn’t block the rest of the page, which is useful for gracefully handling in-progress form entry without risking accidental data loss on dismiss.
